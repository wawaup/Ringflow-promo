# Ringflow 宣传片逐秒内容稿

版本依据：当前 Remotion 工程 `RingflowPromo`，1920x1080，60fps，总时长约 56.10 秒。  
用途：给其他 AI、动画师、剪辑师或前端实现者阅读；即使不看代码和视频，也能理解每秒画面内容、文字、动效、位置、样式和表达意义。

---

## 全片视觉规则

- **整体风格**：苹果风、macOS 原生感、浅色蓝白渐变为主，局部深色蓝灰用于自动化/系统监视类功能。
- **背景**：浅色场景使用 `#f8fbff -> #edf7ff -> #ffffff` 斜向渐变，叠加一条从左下到右上的柔白丝带曲线；深色场景使用 `#07111f -> #142238 -> #26364e` 蓝灰渐变。
- **字体**：系统字体栈，接近 SF Pro Display / PingFang SC；大标题粗重，字重约 820；字幕/标签字重 620-760。
- **文字版式**：
  - 左文右图场景：左侧文字区宽约 700px，位于安全区内，垂直居中，左对齐。
  - 上文下图场景：文字横向居中，位于画面上方偏中区域，视觉主体在下方居中。
  - 品牌/理念场景：文字与主体居中。
- **常用组件样式**：
  - macOS 窗口：圆角 22-30px，半透明白色玻璃，细白色描边，柔和阴影，顶部有红黄绿三色窗口按钮。
  - 轮盘：浅色玻璃环形 UI，中心圆为半透明白色，扇区有极细分割线；高亮扇区使用淡蓝填充与蓝色描边。
  - 深色场景组件：深蓝灰玻璃面板，白色细描边，文字为浅灰蓝，强调色为蓝色或绿色。
  - 键盘键帽：白色半透明圆角矩形，细灰蓝描边，文字为深蓝灰粗体，如 `Control`、`C`、`V`。
- **动效原则**：文字先建立主题，再进入视觉主体，最后执行具体动作，动作完成后停留半拍。所有动画使用帧驱动的透明度、位移、缩放、模糊或弹簧，不使用 CSS transition。

## 逐秒稿

### 0-1 秒：第一页整屏进入

- **画面**：浅蓝白背景已经出现。右侧约画面 48%-93% 宽度区域出现一个大型半透明工作区面板，位置在画面右半边，面板圆角约 30px。
- **文字**：暂无主标题。
- **动效**：整个第一页工作区从模糊、低透明、轻微缩小和轻微下移状态渐进进入；面板内部右侧已经能隐约看到两个小 Dock 图标：上方黄色“纪”，下方白蓝“提”。
- **样式**：工作区像一块磨砂玻璃，背景内部有柔和白色光幕从左向右扫入。
- **意义**：给 BGM 和画面加载一个呼吸缓冲，让观众先进入 macOS 工作环境。

### 1-2 秒：第一页标题第一行出现

- **画面**：右侧工作区面板完成入场，但里面还没有主要窗口。左侧开始出现第一行大字。
- **文字**：左侧出现 `正在做的事，`。
- **动效**：文字从下方约 28px 轻微上移，同时透明度从 0 到 1，并用裁切遮罩从上到下展开。
- **位置**：文字位于左侧安全区内，约 x=120，垂直居中偏上，左对齐。
- **意义**：先提出核心情绪：用户本来正在专注做事。

### 2-3 秒：第一页标题第二行出现

- **画面**：左侧标题第二行加入，右侧工作区保持安静。
- **文字**：第二行出现 `应该保持连贯。`，与第一行组成 `正在做的事，应该保持连贯。`
- **动效**：第二行比第一行晚约 0.4 秒出现，同样是淡入、上移、遮罩展开。
- **样式**：大标题深蓝黑色，字号约 88px，行高紧凑，强视觉重量。
- **意义**：明确本片的价值主张：操作不应该打断当前任务。

### 3-4 秒：Codex 工作上下文进入

- **画面**：右侧工作区中开始出现两个 Codex 窗口：一个主对话窗口，一个输入框。
- **文字**：
  - 主窗口标题：`Codex · 项目对话`
  - 主窗口内容包括：`当前任务：实现订阅状态刷新与预设导入验证。`
  - 输入框标签：`Codex 输入框`
- **动效**：Codex 主对话窗口从下方轻微上移并淡入；输入框随后进入。
- **位置**：
  - 主对话窗口在右侧工作区上半部偏左。
  - 输入框在主窗口下方，宽度约 574px。
- **意义**：建立具体工作场景：用户正在一边看项目上下文，一边准备向 Codex 输入。

### 4-5 秒：便签窗口进入

- **画面**：右上方出现黄色便签窗口，Dock 上的“纪”图标表现为已被点击/激活。
- **文字**：
  - 便签标题：`会议纪要`
  - 内容：`下次同步前确认三件事：订阅状态刷新点、设备解绑入口、预设导入后的默认轮盘。`
- **动效**：便签窗口从右侧轻微滑入并淡入；Dock 上“纪”图标轻微上浮、放大。
- **样式**：便签顶部为淡黄色栏，内容区为半透明白色，文字较小但可读。
- **意义**：表现用户要对照会议纪要继续开发，需要在多个窗口之间切换。

### 5-6 秒：复制会议纪要

- **画面**：便签内容区域出现淡蓝色选中高亮；画面底部中间出现 `Control` + `C` 键帽。
- **文字**：键帽显示 `Control` 和 `C`。
- **动效**：
  - 便签文本区域出现蓝色选择覆盖层，表示选中全部会议纪要。
  - 键帽从下方轻微上移并淡入。
- **位置**：键帽位于右侧工作区底部中央，输入框下方。
- **意义**：明确传统操作中需要选中、复制，表现实际成本。

### 6-7 秒：粘贴会议纪要到 Codex

- **画面**：Codex 输入框内出现会议纪要内容；底部键帽变为 `Control` + `V`。
- **文字**：
  - 输入框内出现：`会议纪要：确认订阅刷新、设备解绑、预设导入默认轮盘。`
  - 键帽显示 `Control` 和 `V`。
- **动效**：
  - 输入框内容像被粘贴一样突然出现。
  - 键帽淡入后短暂停留。
- **意义**：表现第一轮跨窗口复制粘贴完成，但过程已经打断了专注流。

### 7-8 秒：打开常用提示词

- **画面**：右侧打开 Mac 记事本窗口，标题为常用提示词；Dock 上“提”图标表现为被点击/激活。
- **文字**：
  - 窗口标题：`Mac 记事本 · 常用提示词`
  - 列表项：`总结提炼`、`润色`、`改写`、`分步说明`、`对比分析`
- **动效**：提示词窗口从右侧滑入；列表项稳定显示；`总结提炼` 项处于淡蓝色高亮选中状态。
- **位置**：提示词窗口位于右侧工作区偏右中部，叠在便签下方但不遮挡输入框主体。
- **意义**：展示用户还需要再打开一个保存常用提示词的窗口，操作链条继续变长。

### 8-9 秒：复制并粘贴提示词

- **画面**：`总结提炼` 被高亮，底部出现 `Control` + `C`，随后变为 `Control` + `V`。
- **文字**：
  - 键帽：`Control` + `C`，随后 `Control` + `V`
  - 输入框补充出现：`总结提炼，并拆成可验证步骤。`
- **动效**：
  - `总结提炼` 项有轻微放大和蓝色高亮加强。
  - 键帽提示切换。
  - 输入框文本追加出现。
- **意义**：强调“只是准备一段输入”就已经需要复制会议纪要、复制提示词、切换多个窗口。

### 9-10 秒：开场情绪停留

- **画面**：左侧大标题完整显示；右侧三个窗口同时可见：Codex 主窗口、Codex 输入框、便签、提示词记事本。
- **文字**：左侧仍为 `正在做的事，应该保持连贯。`
- **动效**：所有元素基本停留，只有输入框光标轻微闪烁。
- **意义**：让观众看清“烦躁感”的来源：不是任务难，而是操作被拆散到多个窗口。

### 10-11 秒：操作绕远场景切入

- **画面**：进入第二幕，左侧文字变为 `找来找去。`，右侧出现第一张菜单卡片。
- **文字**：
  - 左侧第一行：`找来找去。`
  - 右侧卡片标题：`菜单栏`
  - 菜单项：`编辑`、`服务`、`替换`
- **动效**：场景切换为新的浅色背景；菜单卡片淡入上移。
- **意义**：从具体例子抽象到日常操作问题：动作入口太分散。

### 11-12 秒：菜单层层叠加

- **画面**：第二张菜单卡片出现在第一张右下方，形成叠层。
- **文字**：
  - 左侧继续出现：`来回切换。`
  - 第二张卡片标题：`二级菜单`
  - 菜单项：`转换`、`朗读`、`打开方式`
- **动效**：第二张卡片延迟出现，位置比第一张更靠右下，制造操作路径变长的视觉感。
- **意义**：表现为了找到一个动作，用户经常进入二级菜单和复杂路径。

### 12-13 秒：窗口切换压力

- **画面**：第三张卡片出现，标题为 `窗口切换`，整体右侧变成三张重叠菜单。
- **文字**：
  - 左侧第三行：`一遍又一遍。`
  - 第三张卡片内容：`Notes`、`Finder`、`Terminal`
- **动效**：第三张卡片继续叠入；所有卡片形成向右下扩散的堆叠。
- **意义**：强调重复切换带来的烦躁和认知负担。

### 13-14 秒：理念转折

- **画面**：画面变为居中构图，只有大字和一个光标。
- **文字**：`常用的，`
- **动效**：大字居中出现；光标从左下方朝中心缓慢滑动，带淡蓝拖尾。
- **位置**：文字居中偏上；光标在画面中部附近运动。
- **意义**：从问题转向理念：常用动作不应该藏得很远。

### 14-15 秒：理念补全

- **画面**：第二行文字出现，光标继续向中心靠近。
- **文字**：`应该更近一点。`
- **动效**：文字逐行补全；光标拖尾逐渐淡出。
- **意义**：给后续 Ringflow 亮相做铺垫：把动作放到光标附近。

### 15-16 秒：Ringflow 产品亮相开始

- **画面**：顶部居中出现 `Ringflow`，下方是单层轮盘。
- **文字**：`Ringflow`
- **动效**：轮盘从中心弹性缩放出现；光标在轮盘右上方附近淡入。
- **样式**：轮盘为浅色玻璃，中心写 `默认 / 全局` 或 Ringflow 相关中心标签，右上扇区淡蓝高亮。
- **意义**：正式展示产品主体。

### 16-17 秒：产品亮相完成

- **画面**：标题补全为 `Ringflow 出现在光标旁边。`
- **文字**：`出现在光标旁边。`
- **动效**：光标从右侧滑向轮盘右上方，轮盘保持轻微光晕。
- **位置**：文字在画面上方居中；轮盘居中偏下。
- **意义**：表达 Ringflow 的核心位置关系：跟随光标，随叫随到。

### 17-18 秒：轮盘细节停留

- **画面**：单层轮盘清晰展示，扇区标签可见，如常用提示词、复制、粘贴、撤销、全选、新脚本、新便签等。
- **文字**：顶部标题保持。
- **动效**：轮盘和光标基本停留，保留轻微阴影和光晕。
- **意义**：让观众看清 Ringflow 不是抽象图形，而是可执行动作轮盘。

### 18-19 秒：进入核心手势教学

- **画面**：切到核心手势页，顶部居中显示 `按住中键，向右一划。`
- **文字**：第一行 `按住中键，`，第二行 `向右一划。`
- **动效**：文字逐行出现；下方准备显示放大的鼠标。
- **意义**：将产品亮相转为具体操作教学。

### 19-20 秒：鼠标放大教学

- **画面**：画面中央出现放大的鼠标，滚轮/中键区域为蓝色高亮。
- **文字**：顶部标题保持。
- **动效**：鼠标从透明到可见，中键蓝色区域亮起，表示按住中键。
- **样式**：鼠标为白色圆角垂直鼠标造型，阴影柔和，中键蓝色填充。
- **意义**：明确交互方式：不是普通点击，而是按住中键。

### 20-21 秒：向右滑动开始

- **画面**：鼠标从中心向右滑动，留下淡蓝色拖尾和小箭头。
- **文字**：顶部标题保持。
- **动效**：鼠标缩小一点并向右上方移动；箭头方向约向右偏上。
- **意义**：表现“划动”的动作本身，让交互路径可读。

### 21-22 秒：双层轮盘在右侧出现

- **画面**：右侧出现双层 Ringflow 轮盘，鼠标在轮盘左侧，指向右侧扇区。
- **文字**：顶部标题保持；下方开始出现结果提示。
- **动效**：
  - 外层轮盘从轻微旋转状态展开。
  - 右侧目标扇区高亮。
  - 轮盘有蓝色光晕脉冲。
- **位置**：轮盘固定在右侧舞台，鼠标从中间滑到轮盘左侧。
- **意义**：展示只有在中键向右滑动的核心交互中才出现双层轮盘和旋转反馈。

### 22-23 秒：动作完成

- **画面**：轮盘目标扇区保持高亮，底部文字显示 `快捷输入已触发`。
- **文字**：`快捷输入已触发`
- **动效**：鼠标停住；轮盘中心状态从 `按住` 过渡到 `完成`；结果文字淡入。
- **意义**：让观众理解“一划”不是装饰，而是执行了具体功能。

### 23-24 秒：快捷输入功能标题

- **画面**：进入快捷输入页，顶部居中标题出现。
- **文字**：`常用文字，一划输入。`
- **动效**：标题先出现，下方工作区随后进入。
- **意义**：从手势教学进入第一个真实功能：常用文本输入。

### 24-25 秒：快捷输入工作区

### 25-26 秒：提示词插入完成

- **意义**：强调不只是粘贴，还能恢复剪贴板，减少干扰。

### 26-27 秒：快捷打开功能标题

- **文字**：轮盘中心 `打开`。

## 组件与版式补充说明

### SceneShell

- 负责每页统一布局。
- 左文右图模式：左侧文字区宽 700px，右侧视觉区默认 760x600，第一屏扩展为 980x680。
- 上文下图模式：文字在画面上方居中，视觉区约 1040x610。
- 居中模式：文字和主体都居中。
- 视觉主体比文字晚出现，默认使用弹簧式透明度和位移进入。

### PromoText

- 每行文字独立出现，不是整段一起出现。
- 动效：透明度 0 到 1；Y 方向从 28px 上移到 0；底部 clip-path 从 100% 到 0，形成向下揭开的文字感。
- 第一屏行间延迟更长，先出现 `正在做的事，`，再出现 `应该保持连贯。`。

### InterruptedWorkflowWorkspace

- 第一屏专用组件。
- 右侧工作区由一个半透明大面板、Codex 主窗口、Codex 输入框、便签窗口、Mac 记事本常用提示词窗口、两个 Dock 图标和底部键帽组成。
- 整屏入场：工作区整体从模糊 10px、缩放 0.92、下移 34px、低透明状态恢复到清晰。
- 目的：表现开发者在 Codex、会议纪要、常用提示词之间来回复制粘贴，形成“做事被打断”的烦躁感。

### RingflowWheel

- 单层轮盘用于产品亮相和普通功能展示。
- 双层轮盘只在核心手势页使用：鼠标按住中键并向右滑动后，轮盘在右侧出现，外层带旋转展开。
- 高亮色为淡蓝；中心圆为玻璃质感；标签小而清晰，接近真实官网轮盘 UI。

### MacWindow / FeatureCard / Dashboard Cards

- MacWindow：圆角 24px，顶部三色按钮，玻璃背景，适合便签、Terminal。
- FeatureCard：白色或淡蓝玻璃卡片，用于快捷指令完成反馈。
- Dashboard Cards：深色玻璃卡片，用于 CPU、内存、网络、电池状态。
